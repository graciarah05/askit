# Askit v1.3 · Google 도구 선택과 프롬프트 검수

검수일: 2026-11-10. Google 공식 문서를 우선하고, 실제 로그인된 웹 화면과 결과를 대조했다. OpenAI·Anthropic 문서는 공통 설계 원칙을 교차 확인하는 보조 근거로만 사용했다. Google/DeepMind 소속자의 내부 검수가 아니며, 공개 문서 전체를 빠짐없이 조사했다는 의미도 아니다.

[최종 보호된 Preview](https://askit-gb3d9bpue-graciarah05-2261s-projects.vercel.app/) · Vercel 로그인 필요. 공개 Production의 유료 API와 공유 커뮤니티는 개방하지 않았다.

## 1. 이번 결정

프롬프트의 길이나 역할 문구보다 **어느 도구에 어떤 요청을 넣어 실제 결과를 만들 수 있는가**를 우선했다. Askit은 Argon으로 요청을 정리하고, 최종 결과는 사용자가 안내된 Google 도구에서 만든다. 외부 도구의 메뉴를 자동으로 선택하거나 파일을 자동 첨부했다고 표시하지 않는다.

| 사용자 작업 | 추천과 이유 | 만들어 주는 요청 |
|---|---|---|
| 설명·짧은 초안·구성안·대본 | Gemini 일반 채팅. 추가 설정이 불필요 | 원하는 결과부터 받는 요청 |
| 질문에 답하며 개념 공부 | Gemini 가이드 학습. 한 질문씩 이해 확인 | 정답을 먼저 공개하지 않고 질문·힌트로 진행 |
| 실제 슬라이드 초안 | Gemini Canvas. 작성·수정·내보내기 지원 | 슬라이드 본문과 발표 메모 분리, 전체 장수·시간 명시 |
| 새 출처를 찾아 조사 | Gemini Deep Research. 검색과 다중 출처 비교 | 질문·지역·기간·비교 기준, 조사 계획 확인, 1차 출처 |
| 내용 자료 두 개 이상 요약·비교·퀴즈 | Gemini Notebook. 소스 선택과 원문 인용 확인 | 선택한 소스만 사용, 자료 밖 내용은 없다고 표시 |
| 이미지 생성·편집 | Gemini 이미지 | 실제 이미지 생성/편집 요청, 변경·유지 요소·정확한 글자 |
| AI로 영상 생성 | Google Flow의 Omni 1.2 Flash | 장면을 직접 묘사한 클립별 요청, 길이·비율·출력 수 |

두 자료 기준은 Google의 필수 규칙이 아니라 Askit의 보수적인 시작 규칙이다. 디자인 참고 파일은 자료 수에 포함하지 않는다. 직접 입력한 임의 작업은 현재 일반 채팅으로 연결한다. 모든 자유 입력 의도를 자동으로 정확히 분류한다는 주장은 하지 않는다.

Omni는 별도 독립 앱 이름으로 안내하지 않는다. Gemini 앱과 Flow에서 사용할 수 있는 영상 모델이며, 이번 흐름에서는 클립 설정과 연결을 다룰 수 있는 Flow를 선택했다. Flow는 모바일 편집이 완전히 최적화된 도구가 아니므로 장면 연결·내보내기는 컴퓨터 사용을 안내한다. 무료 여부만을 이유로 특정 유료 가입을 강요하지 않는다.

## 2. 공식 근거의 우선순위

| 근거 | 적용한 원칙 | 그대로 옮기지 않은 항목 |
|---|---|---|
| [Google Gemini prompting strategies](https://ai.google.dev/gemini-api/docs/prompting-strategies) | 명확한 과제·맥락·제약·출력 형식, 필요한 예시, 반복 평가 | 모든 작업에 긴 역할 선언·과도한 세부 지시를 일괄 추가하지 않음 |
| [Google Workspace 효과적인 프롬프트](https://workspace.google.com/resources/ai/writing-effective-prompts/) | 작업·맥락·대상·형식을 자연어로 표현, 후속 수정 | 사용자가 네 요소를 별도 문항으로 모두 작성하게 하지 않음 |
| [Google 교육 AI 활용 사례](https://edu.google.com/intl/ALL_us/resources/higher-edu-ai-use-cases/) | 수업 준비·학습·자료·발표 등 실제 교육 상황 중심 | 사례의 존재를 대학생 재방문율이나 학습 성과의 증거로 사용하지 않음 |
| [Google Omni prompting](https://ai.google.dev/gemini-api/docs/omni) | 주체·행동·카메라·빛·소리, 단일 숏·정확한 문구, 변경/유지 구분 | API의 파라미터와 한도를 소비자 앱 메뉴로 표시하지 않음 |
| [OpenAI prompt engineering](https://developers.openai.com/api/docs/guides/prompt-engineering) | 지침·자료 분리, 관련 예시, 변경 전후 평가 | GPT 전용 매개변수·추론 설정을 Argon에 적용하지 않음 |
| [Anthropic prompting overview](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/overview), [best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices) | 성공 기준·실증 평가 선행, 명료한 지시, 과잉 지시 경계 | Claude 전용 동작·effort·예시 개수를 Gemini의 규칙으로 단정하지 않음 |

기존 [Google 프롬프트 조사](GOOGLE-PROMPT-RESEARCH.md)의 멀티모달·긴 문맥·파일·구조화 출력·근거 범위 검토도 유지했다. 공통점은 명확한 과제와 맥락, 자료와 지시의 구분, 필요한 형식, 실제 결과를 통한 수정이다. 프롬프트만으로 비용·대기시간·모델 한계까지 해결된다고 보지 않는다.

### 실제 도구 안내에 사용한 Google 자료

- [Canvas](https://support.google.com/gemini/answer/16047321?hl=ko): 슬라이드와 내보내기. 실제 웹 메뉴에서 `+ → 도구 더보기 → Canvas`, `내보내기 → 프레젠테이션/PDF/PPTX` 확인.
- [Deep Research](https://support.google.com/gemini/answer/15719111?hl=ko): 소스·조사 계획·조사 시작. 5~10분은 공식 일반 안내이며 이번 실측 시간이 아니다.
- [가이드 학습](https://support.google.com/gemini/answer/16448384?hl=ko): 단계적 학습. 미국 영어의 일부 교육 연계를 한국 계정에 보장하지 않음.
- [이미지 생성·편집](https://support.google.com/gemini/answer/14286560?hl=ko): 참고 이미지·수정, 계정·연령 제한. Gemini와 Flow의 이미지 모델 이름을 혼용하지 않음.
- [Gemini Notebook 시작](https://support.google.com/gemininotebook/answer/16206563?hl=ko), [소스 추가](https://support.google.com/gemininotebook/answer/16215270), [소스 기반 채팅](https://support.google.com/gemininotebook/answer/16179559): 현재 공식 명칭을 사용하되 일부 화면의 NotebookLM 표기도 설명.
- [Gemini 동영상](https://support.google.com/gemini/answer/16126339?hl=ko): Omni 접근 및 계정 조건.
- [Flow 시작](https://support.google.com/flow/answer/16353333?hl=ko), [모델·지원 기능](https://support.google.com/flow/answer/16352836?hl=ko), [생성·편집](https://support.google.com/flow/answer/16935718?hl=ko), [크레딧](https://support.google.com/flow/answer/16526234?hl=en): 모델·길이·화면 비율·장면 연결, 이용 제한.

문서와 실제 계정 화면이 다르면 확인된 메뉴를 안내하고 계정·기기 차이를 표시한다. 링크와 메뉴는 모델이 임의 생성하지 않고 검토된 목록에서 제공한다. 제품 변경 시 위 자료와 화면을 함께 재확인해야 한다.

## 3. 입력 부담과 프롬프트 계약

필수 질문을 추가하지 않았다. 할 일을 한 문장으로 쓰고 결과 종류를 고르면 시작할 수 있다. 과제 조건·자료·세부 설정은 선택이다. 주요 선택 항목에는 직접 입력을 유지했다. 이미 받은 정보는 다시 묻지 않는다. 결과를 만들 수 없는 필수 충돌만 한 번 확인한다.

- 공통: 목표, 결과 형식, 필요할 때 대상·언어·분량·과제 조건.
- 자료: 내용 근거, 과제 평가 기준, 디자인/배치, 수정할 원본, 결과 형식, 직접 설명으로 구분. 템플릿의 예시 수치를 사실로 쓰지 않음.
- 발표: 전체 장수(부록·출처 포함), 전체 시간, 청중, 슬라이드 내용과 메모 분리. 외부 사진이 꼭 필요하지 않으면 도형·도식 우선.
- 조사: 조사 질문·지역·기간·대상·비교 기준. 발행일과 실제 조사 시점을 구분하고 1차 출처를 확인.
- 이미지: 주체·배경·구도·스타일 중 필요한 요소, 정확한 글자, 변경할 부분·유지할 부분. 원본 없는 편집은 원본 필요성을 표시.
- 영상: 전체 길이·화면 비율·장면·소리·정확한 글자·참고 이미지. 1분 30초를 90초로 읽고, 장면 수와 생성 횟수를 구분.

Flow의 일반 접근 범위에 맞춰 클립을 3~10초로 나눈다. Askit 한 번의 준비 범위는 총 3~120초이며 이는 Google 자체 한도가 아니다. 15초는 8+7초, 90초는 10초×9개로 구성한다. 지정하지 않은 8초·9:16은 제안이라고 표시한다. 지원되지 않는 1:1은 그대로 가능하다고 하지 않고 생성 후 자르기가 필요하다고 표시한다. 서로 다른 전체 길이를 명시하면 임의로 8초를 선택하지 않고 확인을 요청한다.

Flow에 복사되는 내용에는 ‘프롬프트를 써 줘’, 표, 검수 목록, 일반 채팅용 자료 구분문을 넣지 않는다. 선택한 클립의 영상 묘사만 복사한다. 각 클립은 다른 클립의 문맥을 보지 않아도 인물·배경·스타일을 알 수 있어야 한다. 각 생성에 크레딧이 들 수 있으므로 첫 클립부터 확인하도록 안내한다.

## 4. 평가 루브릭

점수는 실제 측정 없는 인상을 숫자로 바꾸는 용도로 쓰지 않았다. 아래 항목별 확인과 탈락 조건으로 평가한다. 소프트웨어 동작 통과와 생성 콘텐츠 품질 통과를 분리한다.

| 항목 | 확인 방법 | 탈락/보류 기준 |
|---|---|---|
| 도구 적합성 | 15개 작업·자료 조합의 추천 경로, 공식 기능과 대조 | 구성안만 원하는데 영상 생성창으로 전송, 근거 자료 대신 템플릿으로 조사 |
| 실행 가능성 | 실제 메뉴·버튼·붙여넣기·내보내기 확인 | 존재하지 않는 메뉴/모델, 메타 요청을 영상창에 복사, 파일 생성 허위 주장 |
| 조건 보존 | 장수·시간 합계·글자·소리·참고 범위 검사 | 필수 조건 누락·충돌 묵살·다른 클립 복사 |
| 근거·정확성 | 원문·자료 역할·예시의 필수 전제 검토 | 수치·출처 조작, 관찰하지 않은 첨부를 봤다고 주장, 개념에 어긋난 예시 |
| 사용 부담 | 모바일 화면·선택/직접 입력·복사·수정·저장 직접 사용 | 추가 필수 설문, 반복 입력 강제, 가로 넘침, 핵심 버튼 가림 |
| 실패 복구 | 기본 프롬프트·도구별 대체 요청·원래 조건 재검사 | 이용 불가 시 막힘, 대체 요청을 완성 파일 생성처럼 표현 |

단위검사 123개가 통과했다. 이는 실제 모델이 모든 주제에서 좋은 답을 한다는 증거가 아니다. Flow 생성 영상의 품질·연속성, 사용자 만족도·재방문율·가입률은 별도 검증이 필요하다.

## 5. 실제 실패 → 수정 → 재검수

1. 초기 클립 구조를 포함한 API 요청 한 건이 공급자 오류로 실패했다. 출력 스키마의 배열 복잡도를 낮추고, 클립 개수·시간은 서버에서 엄격히 검증하도록 바꾼 뒤 성공했다. 단 한 번의 관찰로 공급자 내부 원인을 확정하지 않는다. 자동 유료 재시도는 추가하지 않았다.
2. 15초 영상의 첫 응답에 요청하지 않은 실내 주변 소리가 추가됐다. ‘종이 소리만’처럼 배타적인 소리 조건을 보존하도록 수정하고 재생성한 두 클립에서 확인했다.
3. 실제 Flow는 새 프로젝트에서 에이전트가 켜져 있었다. 바로 영상 설정을 찾으라는 안내로는 막힐 수 있어 ‘에이전트 끄기 → 설정 → 동영상 → Omni 1.2 Flash’를 반영했다. 기본 출력 두 개 대신 한 개를 명시하고 크레딧 표시 확인을 안내했다. 실제 영상 생성은 수행하지 않았다.
4. Canvas v6 결과는 배치 지시와 대본이 본문에 섞였다. 실패로 기록하고 본문/메모 분리를 강화했다.
5. v7은 메모가 분리됐지만 자동 이미지 출처 페이지로 전체가 5장이 됐다. 실패로 기록하고 전체 장수에 부록·출처 포함, 도형 중심 시각화로 수정했다.
6. v8 실제 Canvas와 내려받은 PPTX는 4장이었다. 발표 시간 배정은 30+50+50+50=180초, 대본은 채팅의 별도 영역에 있었다. **PPTX에는 메모가 없었다.** 대본을 별도로 보관하도록 안내를 보완했다.
7. v8에서도 마지막 예시의 환불 불가 전제가 명시되지 않았고 기회비용 표현 일부는 검토가 필요하다. 따라서 내용 정확성 전체를 완전 통과로 표시하지 않았다. 결과 화면에 ‘조건 다시 확인’을 추가해 원래 요청과 대조한 수정 요청을 복사할 수 있도록 했다. 실제 낭독 시간도 측정하지 않았다.
8. 자료 두 개를 첨부하고 용도를 바꿀 때 추천 미리보기가 갱신되지 않는 문제를 고쳤다. 내용 자료→디자인 참고→내용 자료 변경 시 Gemini→Gemini Notebook 전환을 직접 확인했다.
9. 복사 전에 새 탭을 열면 브라우저가 클립보드 접근을 거부하는 문제를 발견했다. 복사 완료 후 탭을 열도록 수정하고, 실제 클립 복사와 Flow 새 탭, 촬영 계획 대체 요청 복사를 확인했다. 복사 거부 시 직접 복사 창도 유지한다.
10. 390×844 화면에서 실행 버튼이 하단 메뉴에 걸리던 여백을 조정했다. 검수 결과 버튼 하단 약 696px, 하단 메뉴 시작 769px로 분리됐다. 클립 전환·선택 클립만 복사·수정 저장·재열기 확인.

증거는 `qa/workflows/`에 있다. `live-*`는 실제 API 결과이고, `serve-replay.mjs`는 그 결과를 모바일에서 재생한 UI 검수용이다. 재생 검사를 새 모델 생성으로 세지 않았다. `canvas-downstream-v6/v7-review.json`의 실패 기록도 삭제하지 않았다.

## 6. 시간·비용과 증거의 한계

이번 도구 연결 작업의 API 요청: 성공 7건, 초기 오류 1건. 성공 건의 서버 처리 시간 11.901~36.469초, 표준 토큰 단가 기준 합계 **US$0.101578**. 90초/9클립 요청은 36.469초, 약 US$0.030092였다. 마지막 v8 발표 요청은 11.901초, 약 US$0.013196였다.

실제 청구 확정액이 아닌 토큰 사용량 기반 추정이며 Vercel·세금·최종 정산·Gemini 웹 사용·Flow 크레딧을 포함하지 않는다. 오류 요청의 사용량은 알 수 없으므로 0달러로 계산하지 않았다. 원자료: `qa/workflows/live-metrics.json`. 이전 v1.2 실험과 대조군 한 건은 이번 수치에 합산하지 않았다.

이번 소수 사례는 도구 연결과 발견된 결함의 수정 근거다. ‘일반적인 프롬프트보다 항상 우수하다’거나 개선율 몇 %라고 말할 수 없다. 같은 작업을 여러 번 무작위 순서로 실행하고 독립 평가해야 일반화할 수 있다. 최종 API 버전 v8의 직접 생성은 발표 한 건이고, 영상·조사의 실제 생성은 앞선 버전에서 확인했다. 이후 UI 조정은 모델 계약을 바꾸지 않았다.

## 7. 배포 상태와 남은 경계

- 보호된 Vercel Preview에서 Argon을 사용한다. 모델은 서버가 지정하므로 AI Studio의 화면 모델 선택은 필요 없다.
- 공개 Production의 유료 생성은 아직 닫혀 있다. 공개 운영 전 공유 저장소 기반 요청/예산 제한이 필요하다. 이번에는 인증 보호를 풀지 않았다.
- 커뮤니티 서버 구성은 별도로 유지하며 Supabase 클라우드 연결 전에는 실제 공유 커뮤니티가 열리지 않는다.
- 학생 혜택 링크는 `https://gemini-google.kr/askit`. 추천 결과 카드에 가입 배너·가입 조건을 추가하지 않았다.
- 실제 Notebook/Deep Research 최종 답변, 이미지/영상 최종 생성, 모든 계정·연령·국가·기기의 메뉴를 검증한 것은 아니다.
- Chrome 확장의 파일 업로드 제한으로 실제 배포에서 새 첨부 분석 검사는 완료하지 못했다. 브라우저 권한을 바꾸지 않고 IAB 로컬에서 두 파일 선택·역할·원문·저장 복원을 확인했다. 기존 첨부 전송 단위검사는 통과했다.

이번 최종본은 도구별 실행 안내와 프롬프트를 함께 제공하는 검수된 Preview다. 미검증 항목을 ‘완벽한 품질’ 또는 ‘공개 운영 준비 완료’로 포장하지 않는다.

별도 파일 미리보기: `preview/Askit.html`을 생성하고 자바스크립트 문법을 검사했다. 자동 브라우저의 file: 주소 정책으로 직접 실행 검수는 완료하지 못했다. 웹 UI 검수는 동일 소스의 로컬 HTTP 화면과 실제 Vercel Preview에서 수행했다.
