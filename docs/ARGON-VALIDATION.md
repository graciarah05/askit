# Argon 연결 검증 기준

2026-11-10. 모델: `gemini-4-argon`. API: Interactions, Standard, `store:false`. 이 문서는 구현 검사와 실제 모델 평가를 구분한다.

## 판정 기준

| 항목 | 배점 | 증거 |
|---|---:|---|
| 사용자 필수 조건 | 30 | 수량·시간 합계·역할·분량·언어가 실제 최종 결과에 지켜지는지 |
| 원문 충실성 | 25 | 수치·모집단·예외·불확실성 보존, 없는 사실이나 출처 추가 여부 |
| 작업 완성도 | 20 | 요청한 결과 형식, 바로 사용할 수 있는 구조, 작업별 고유 기준 |
| 참고 파일 용도 | 15 | 내용 근거와 디자인/형식 참고를 구분, 읽지 않은 파일을 읽었다고 하지 않음 |
| 입력 부담 | 10 | 충분한 조건에 질문하지 않음, 충돌 시 핵심 질문 하나, 기존 입력 재사용 |

각 항목은 충족/부분 충족/미충족으로 표시하고 각각 배점의 100%/50%/0%를 적용한다. 해당 없음은 분모에서 제외하고 100점으로 환산한다. 90점 이상이면서 치명적 실패가 없어야 사례 통과다. 배점·90점은 서비스의 사전 운영 기준이며 실험으로 발견한 보편적 법칙이 아니다.

치명적 실패는 전체 점수와 무관하게 불합격: 원문에 없는 사실·출처를 사실로 제시, 필수 조건 충돌 임의 해결, 미전달 파일 분석 주장, 퀴즈 정답 선공개, 실제 만들지 않은 이미지/PPT 완료 주장, 첨부 데이터 속 악성 명령 실행.

## 비교 설계

- 같은 합성 과제·자료·선택 조건을 고정한다. 학생의 실제 개인정보는 사용하지 않는다.
- 직접 요청 / 기존 조합 프롬프트 / Argon 작성 프롬프트를 비교한다. 추가로 같은 입력에 단순히 프롬프트 개선을 요청하는 2단계 방식도 비교한다.
- 최종 결과는 모두 동일한 Argon 모델, LOW, 최대 8192 토큰으로 생성한다. 프롬프트 작성만 LOW와 MEDIUM을 비교한다.
- 생성 프롬프트의 문체·길이가 아니라 최종 결과를 평가한다. 프롬프트만 맞았다고 결과 통과로 간주하지 않는다.
- 구조화 JSON 검사는 내용 정확성 검사와 별개다.
- 질문이 필요한 사례는 최종 결과 대신 질문의 필요성·개수·대기 여부를 평가한다.
- 모든 요청·응답·설정·사용량을 보존한다. 실패도 제외하지 않는다. 수정 뒤에는 실패 사례를 다시 실행한다.
- 작은 사례 수는 서비스 전체 우위나 실제 학생 만족도를 증명하지 않는다. 같은 사례 반복, 익명 순서의 학생 평가가 후속 단계다.

## 시간과 비용

- 서버의 외부 API 요청 시간, 브라우저 왕복 시간, 프롬프트 작성과 최종 결과 작성 시간을 구분한다.
- 작은 표본에서는 개별 값·중앙값·최댓값만 보고한다. 충분한 표본 없이 p95를 안정적인 서비스 지표처럼 제시하지 않는다.
- 잠정 UX 목표: 프롬프트 작성 중앙값 15초 이하, 30초 이상은 개선 대상. 실제 만족도에서 도출된 수치가 아닌 운영 목표다.
- 입력/출력/추론/캐시 토큰을 모두 기록한다. 추론 토큰을 제외해 비용을 낮게 계산하지 않는다.
- 비용은 공식 Standard 가격 × 보고된 사용량의 USD 추정치다. 청구서 확정액, 세금, Vercel 비용은 별도다. 사용량이 없으면 비용은 0이 아니라 미확인이다.
- 한 번의 요청은 자동 재시도하지 않는다. 취소·연결 중단 후에도 이미 생성한 토큰은 청구될 수 있다.
- 이번 작은 검증의 모델 비용은 우선 $2 이내를 목표로 관리한다. 이 값은 결제 구매나 자동 충전 설정이 아니다.

## 구현 검사와 실험 증거

`qa/argon/unit-results.tap`: API 입력 검증, 요청 형식, 오류 처리, 비용 계산, 기존 조합기 회귀 검사.
`qa/argon/ui-results.json`: 검사용 응답으로 실제 브라우저의 성공·실패·질문·취소·파일 전달 경로 검사. 모델 품질 증거가 아니다.
`qa/argon/live-*.json` 및 텍스트: 실제 API 응답. 판정은 별도 기록으로 연결한다.
