# Askit 레퍼런스 충실도 수정·검수

2026-11-10 · 소규모 탐색 검수. 독립 평가·블라인드 평가·반복 표본 실험이 아니며, Askit의 일반적 우월성이나 대학생 재방문 수요를 입증하지 않는다.

## 문제 판단

레퍼런스의 모든 특징이 사라진 것은 아니다. 기존 결과에는 크림색·남색, 굵은 제목, 물결이 남았다. 하지만 포스터의 정보 섬·방향 변화·큰 빈 공간, 카드뉴스의 페이지별 구조를 잃고 일반적인 중앙 정렬 템플릿으로 변했다. 따라서 ‘색·소품만 유사하고 구조가 다르다’는 문제는 확인된다.

이전 검수의 텍스트·수량 조건 충족을 전체 디자인 품질과 혼동하면 안 된다. 원본 공간 관계의 충실도를 별도로 평가하도록 기준을 보완했다. 판정 기준은 `qa/paired/REFERENCE-FIDELITY-PROTOCOL.md`에 재생성 전에 기록했다.

## 공식 근거와 적용

- [Google Gemini의 Nano Banana Pro 가이드](https://blog.google/products-and-platforms/products/gemini/prompting-tips-nano-banana-pro/): 구성·문구·참조별 역할을 명시하고, 바꿀 대상과 유지할 대상을 구분한다. ‘영감만 받기’와 특정 요소를 보존하는 편집은 다른 요청이다. → 파일별 역할, 유지 영역과 새 내용의 대응을 프롬프트에 넣었다.
- [Google Cloud의 이미지 프롬프트 가이드](https://cloud.google.com/blog/products/ai-machine-learning/ultimate-prompting-guide-for-nano-banana): 참고 자료, 참고와 새 결과 사이의 관계, 새 상황을 함께 구체화하고 후속 수정은 범위를 좁힌다. → ‘비대칭’만 나열하지 않고 상·중·하/좌·우, 큰 덩어리, 여백, 정보 위계를 설명하도록 했다.
- [Google DeepMind 이미지 가이드](https://deepmind.google/models/gemini-image/prompt-guide/): 주체·스타일·구성과 참조를 사용하며 짧은 프롬프트도 유효할 수 있다. → 길이를 품질 지표로 쓰지 않고 실제 결과로 검증했다.
- [Google 이미지 생성의 알려진 한계](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/capabilities/gemini-image-generation-limitations): 요청한 이미지 수 등이 정확히 반영되지 않을 수 있다. API 문서의 한계를 소비자 웹의 세부 수치로 옮기지 않는다. 이번 Gemini 웹에서도 한 장만 생성하거나 콜라주로 합치는 실패가 실제 발생했다.

공식 가이드 어디에도 동일 픽셀·정확한 서체·배치를 보장한다는 근거는 없다. ‘구도·배치까지 살리기’는 요청 의도이며 모델의 수치형 참조 가중치 설정이 아니다. 이 문서는 모든 Google 문서를 전수 조사했다고 주장하지 않는다.

## 구현

1. 디자인 참고 파일에서만 ‘구도·배치까지 살리기 / 색·분위기만 참고 / 직접 지정’을 제공한다. 기본값은 첫 항목이며 추가 답변은 필요 없다. 직접 지정할 때만 기존 ‘참고할 부분’에 원하는 요소를 쓴다.
2. 실제 분석에 동의해 보낸 참고에서 위치·상대 크기·방향·여백·반복 장식 등 식별 가능한 특징을 추출하고, 새 문구를 어느 영역에 넣을지 연결한다. 보내지 않은 파일의 특징은 추측하지 않는다.
3. 콜라주 참고에서는 바깥 목업 배경을 제외하고 원본 카드와 새 카드의 대응을 밝힌다. 자동으로 고른 대응은 ‘배치 제안’으로 표시한다.
4. 사용자가 지정한 문구·기호·공통 서체가 원본 스타일보다 우선한다. 가독성 문제를 고친다는 이유로 전체 구도를 다시 중앙 정렬하지 않는다.
5. 여러 장은 결과 화면에서 1장·2장·3장을 골라 복사한다. 각 복사문은 그 장 한 개만 생성하도록 전체 사양과 실행 범위를 분리한다. 다음 장은 같은 Gemini 대화에 붙여넣어 공통 스타일을 이어간다. 사용자가 장별 요청문을 직접 나눠 쓸 필요가 없다.

## 동등 조건과 구분

같은 공개 Pinterest 이미지와 같은 목표·문구·제약, 같은 Gemini 계정과 Flash 선택, 새 대화를 사용했다. UI의 Flash 선택을 기록했으며 숨겨진 이미지 모델 버전을 추측하지 않았다. 각 초기 비교는 한 번씩 실행했다. 시드 고정·모델 내부 버전 통제는 불가능하다.

v12 재검수에서는 양쪽에 ‘구도·배치 적극 유지’를 똑같이 추가했다. P1의 모호한 ‘아래에 정보’는 양쪽 모두 ‘세부 정보’로 바꿨다. 따라서 v9와 v12는 수정 전후 비교이지, 완전히 같은 요청의 승률 비교가 아니다. 마지막 장별 생성은 3회 실행하는 작업 흐름 개선이며, 일반 프롬프트의 1회 실행과 같은 비용의 비교가 아니다.

## 검수 한계와 남은 항목

- 단일 탐색 사례에서 나온 개선을 전체 이미지 품질 보장이나 통계적 우위로 표현하지 않는다. 실제 학생의 작업 완료 시간·수정 횟수·부담을 측정해야 한다.
- 화면 표시용 WebP 다운로드와 원본 크기 PNG를 분리 기록한다. P1 일부 원본 PNG는 1856×2304였으며, 표시용 825×1024만 보고 원본을 평가하지 않는다. 정확한 인쇄 크기가 필요하면 원본 파일에서 확인해야 한다.
- 원본과 동일한 글꼴/픽셀/레이아웃이 필수인 제작은 편집 가능한 디자인 도구에서 마무리해야 한다.
- 자료 분석 D3 재검수는 계산·표본 구성 통제는 개선됐으나 불필요한 후속 질문, 미기재 비용 표현, 최종 대안 선택이 미흡했다. 이미지 수정과 별도로 품질 완료를 주장하지 않는다. V1의 ‘물소리만’ 청취 검수도 미완료다.
- 공개 Pinterest 자료는 비공개 검수에만 사용했고 앱의 공개 자산에 넣지 않았다. 저작자·출처는 비교 화면에 표시했다.
