# Askit v1.1 — 프롬프트 만들기 검수

확인일: 2026-11-09. 이번 검수 대상은 입력 → 조건 조합 → 파일 보관 → 복사/파일 전달 → Gemini 응답까지다. 이전 v1의 173개 검사와 7회 모델 응답은 이번 수치에 포함하지 않는다.

## 판정

코드와 화면의 변경을 완료했다. 현재 최종 요청문과 내용이 정확히 일치하는 **8개 상황에서 18회(각 2회 이상, 퀴즈는 표시 검증 2회 추가)**의 텍스트 응답이 정의한 내용 조건을 충족했다. 이것은 고정된 사례의 내부 검수 결과이며 모든 과제에서 일반 요청보다 낫다는 증거는 아니다. 실제 대학생을 대상으로 한 사용성 실험이나 독립 평가자의 블라인드 평가는 하지 않았다.

이미지 편집은 **부분 확인**이다. 실제 Gemini에 원본을 첨부해 파란 원을 빨간색으로 바꿨고, 1024×1024 크기와 원/정사각형의 위치는 유지됐다. 그러나 주황색의 픽셀 값과 일부 배경 값이 바뀌었으므로 픽셀 단위 보존은 불합격이다. 이 실패를 텍스트 통과 수로 상쇄하지 않는다. 로고·정확한 브랜드 색·인쇄 원본의 완전한 보존을 보장할 수 없다.

## 입력을 다시 나눈 이유

| 조건 | 입력하는 때 | 변경 |
|---|---|---|
| 작업·결과 형태 | 항상 | 한 줄 설명과 원하는 결과. 요약·퀴즈는 주제 대신 자료 전달 방식 |
| 내용 자료·수정 원본 | 해당 작업일 때 | 붙여넣기 / 파일 첨부 / Gemini에서 첨부 |
| 파일의 사용 목적 | 첨부했을 때만 | 내용 근거 / 과제 기준 / 디자인 / 수정 원본 / 형식 / 직접 설명 |
| 분량·시간·개수 | 제한이 있을 때 | 발표 시간과 장수, 문제 유형과 수, 영상 길이와 장면 수를 각각 선택 |
| 청중·이해 수준 | 결과에 영향이 있을 때 | 작업에 필요한 항목만 선택적으로 표시 |
| 시각 조건 | 이미지·발표·영상 | 비율·스타일·정확한 문구·유지할 것·변경할 것 |
| 과제의 필수 지시 | 지시문이 있을 때 | 한 칸에 붙여넣기. 기본 선택보다 우선. 동급 충돌이면 질문 하나 |
| 사실·출처 범위 | 자동 적용 | 원문 제한, 미확인 원인/효과 구분, 파일을 읽지 않았으면 대기 |

임의로 묶였던 ‘10분·8장’ 등을 제거했다. 모든 선택에는 직접 입력이 있다. 선택하지 않은 수량은 요청에 넣지 않는다. 세부 조건은 접어 두며, 입력한 경우 ‘7분 · 6장’처럼 적용 내용을 요약해 보여준다. 학년·전공·학교를 일괄 필수로 묻지 않는다.

## 발견 → 수정 → 재확인

| 실제 발견 | 수정 | 수정 후 관찰 |
|---|---|---|
| 요약이 원문 인용을 길게 이어 붙임 | 자료 번호를 부여하고 자연스러운 요약 뒤 근거 번호 연결 | 3문장·수치·한계 보존, 긴 인용 반복 제거 |
| 확인되지 않은 도서관 문제 원인을 단정 | 제공되지 않은 현황과 원인은 확인 질문으로 작성 | 6장·7분 충족, 원인을 가설/확인 질문으로 제시 |
| 혼자 촬영인데 카페 주문·음료 수령 장면 필요 | 얼굴을 가려도 타인의 행동이 필요하면 제외, 시설 대체안 요구 | 타인 없이 촬영할 장면과 개인 공간 대체안 |
| 계획 표의 모든 행에 ‘사실/제안’ 반복 | 전체가 제안이면 처음에 한 번만 표시 | 반복 안내를 줄인 5일 계획 |
| 파일 용도 오류 뒤 입력 위치가 불분명 | 문제가 된 용도 선택/직접 설명 칸으로 이동 | 오류 수정 후 같은 자료로 생성 가능 |
| 작은 파일이 0.0MB로 표시 | KB 단위 사용 | 파일 크기를 구별할 수 있음 |
| 접힌 조건에 이전 선택이 숨어 있음 | 접힌 제목에 적용 조건 요약 | 저장된 시간·장수 확인 가능 |

최초 실패 응답도 `qa/prompt-v2/live-results.json`에 보존했다. 실제 요청문, 반복 번호, 응답, 표시된 모델(Flash), 시간 기록이 있다. 현재 요청문 해시와 평가 근거는 `assessment.json`에 있다. 수정 전후를 섞어 합격률을 계산하지 않는다.

## 파일과 전달 흐름

이미지(PNG/JPG/WebP), PDF, PPTX, DOCX, XLSX, TXT/MD/CSV를 선택할 수 있다. 최대 5개·각 20MB·합계 50MB는 **Askit의 브라우저 보관 제한**이며 Gemini의 업로드 한도가 아니다. 파일별 용도를 반드시 구분하고 상세 설명은 필요할 때만 적는다.

파일은 서버로 전송하지 않는다. IndexedDB에 저장하며 저장이 불가능하면 현재 탭에만 보관된다고 표시한다. 짧은 UTF-8 TXT/MD/CSV는 본문을 프롬프트에 넣는다. 이미지·PDF·PPTX 등의 내용을 Askit이 분석한 것처럼 표시하지 않는다. 해당 파일은 Gemini에서도 첨부해야 한다. 프롬프트와 파일의 ZIP 내보내기를 제공한다.

실제 검수에서 이미지 2개 선택, 용도 지정, 새로고침 후 복원, 삭제, 보관함 재열기, 텍스트 파일 포함, ZIP 다운로드 및 압축 무결성을 확인했다. 파일 원본이 없으면 재첨부를 요청한다. 파일별 크기/개수/중복/지원 형식, 저장 불가 시 임시 보관, HTML 이스케이프도 코드 검사에 포함했다.

## 일반 요청과 비교하는 방법

발표·요약·영상에서 **같은 사용자 정보**를 전달한 일반 요청을 각각 두 번 실행했다. Askit만 추가 자료를 받게 하지 않았다. 서로 다른 답변의 문체를 임의로 점수화하지 않고, 명시된 시간·수치·조건과 원문 충실성을 비교했다.

- 발표: 일반 요청도 6장·7분은 두 번 충족했다. 그러나 미확인 현황/원인을 사실처럼 서술했다. Askit 수정본은 해당 내용을 확인 질문으로 바꿨다.
- 요약: 일반 요청 한 번은 사실 관계를 보존했다. 다른 한 번은 ‘전체 수강생 수 미공개’를 ‘전체 수강생 수 조사 미실시’로 바꿨다. Askit 수정본 두 번은 이 차이를 보존했다.
- 영상: 일반 요청 두 실행에는 ‘수업 끝날 때까지 시원함 그대로’, ‘쓰레기 없는 하루’처럼 확인되지 않은 효과를 보장하는 문구가 있었다. 최종 Askit은 보장 표현을 피하고 혼자 가능한 장면을 구성했다.

이는 이 사례에서 관찰한 차이다. 총점 우위·통계적 유의성·실제 학업 성과·장기 재방문 효과는 입증하지 않았다. 제공 자료 자체가 틀린 경우를 검증하는 사실 확인 서비스도 아니다.

## 화면·코드 검수 범위

- 프롬프트/파일/이전 선택 이전: 53개 코드 검사 통과 (`unit-results.tap`).
- 직접 입력 → 생성, 조건 독립, 자료 역할 오류 복구, 수정·복사·새로고침 등 실제 UI 검수 (`ui-results.json`).
- 320·390·430·768·1440px × 8화면의 가로 넘침 40개 검사 통과 (`layout-results.json`). 실제 모바일 기기 실험은 아님.
- 수정 화면의 런타임 오류 없음. 파일을 첨부한 상태의 이미지 미리보기와 저장을 확인.
- 단일 HTML은 생성 및 스크립트 문법을 검사. **file:// 직접 실행 검수는 브라우저 보안 정책에 차단되어 미검증**. 이를 우회하지 않았으며 통과 수에 포함하지 않음.
- Vercel 공개 배포, Gemini API, 실제 공유 커뮤니티 서버는 이번 검수에 포함하지 않음. 기존 커뮤니티 구성은 별도이며 연결 설정 없이는 닫힘 상태.

## 공식 자료

- [Google Gemini 프롬프트 전략](https://ai.google.dev/gemini-api/docs/prompting-strategies): 명확한 목적·제약, 구조 구분, 멀티모달 맥락 연결.
- [이미지 생성](https://ai.google.dev/gemini-api/docs/image-generation): 장면·구도·정확한 문구·참조 이미지·변경/보존 조건.
- [이미지 이해](https://ai.google.dev/gemini-api/docs/image-understanding): 읽을 수 있는 입력과 이미지 간 관계.
- [Gemini 파일 업로드](https://support.google.com/gemini/answer/14903178?hl=ko): 실제 첨부와 로그인 필요.
- [Canvas 사용](https://support.google.com/gemini/answer/16047321?hl=ko): 슬라이드 형식을 명시하고 참고 자료를 함께 제공하는 흐름.

공식 문서의 API 지침을 Gemini 웹의 동일 기능 지원 보장으로 해석하지 않는다. 이번 응답 검수는 Gemini 웹의 Flash 표시 환경에서 수행했으며 내부 모델 버전은 확인하지 못했다. 개념 설명·보고서는 입력/조합 검사에 포함했지만 이번 최종 모델 실험의 직접 대상은 아니다. 실제 PPTX 생성, 복잡한 표/스캔, 다중 파일 장문, 이미지의 정확한 한국어 글자 렌더링은 추가 검증이 필요하다.
