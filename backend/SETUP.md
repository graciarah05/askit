# 공유형 커뮤니티 연결

프롬프트 기능과 독립된 구성입니다. 기존 Supabase 프로젝트의 테이블과 충돌하지 않도록 **새 프로젝트**를 기준으로 합니다. 이 파일은 연결 지침이며 연결 완료 보고가 아닙니다.

1. Supabase 프로젝트를 만들고 SQL Editor에서 `schema.sql`, 이어서 `storage.sql`을 실행합니다. 두 파일은 새 프로젝트에 한 번 적용하도록 작성했습니다. 기존 테이블 삭제 명령은 없습니다.
2. Auth에서 이메일 인증을 켜고 익명 가입은 끕니다. Email Templates의 Magic Link 템플릿을 인증번호 방식으로 바꿉니다. 본문에 `{{ .Token }}`을 넣습니다. 이 앱은 메일 링크가 아닌 인증번호를 검증합니다.
3. 공개 서비스에는 사용자에게 실제 메일을 보낼 수 있는 SMTP를 설정합니다. 기본 테스트 발신 환경만으로 외부 학생에게 전달된다고 가정하지 마세요. 메일 발신 도메인과 전송 한도를 확인합니다.
4. Auth URL Configuration에 최종 배포 주소를 등록하고 이메일 OTP 만료·재전송 제한을 설정합니다. 필요 시 CAPTCHA를 추가할 때는 화면의 토큰 전달도 함께 구현해야 합니다. 대시보드에서 CAPTCHA만 켜면 현재 인증 요청은 실패합니다.
5. Vercel 환경변수에 아래 **공개 설정**을 등록합니다. Gemini 키, `service_role`, `sb_secret_` 키는 넣지 않습니다.

```text
PUBLIC_SUPABASE_URL=https://프로젝트ID.supabase.co
PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
PUBLIC_COMMUNITY_ENABLED=true
```

6. 운영 주체의 이름·문의 이메일·계정 삭제 요청 창구와 실제 데이터 보유 기준을 `public/app.js`의 개인정보 안내에 반영합니다. 앱이 임의로 운영자 연락처를 만들어 넣지는 않았습니다. 이것이 완료되기 전에는 공개 커뮤니티를 개통하지 마세요.
7. 다시 빌드·배포한 뒤 실제 두 계정으로 아래 절차를 통과하면 커뮤니티를 공개합니다.

## 실제 연결 후 통과해야 하는 확인

- A와 B가 각각 이메일 인증번호를 받고 로그인한다.
- A가 글·이미지·활용 사례 프롬프트를 등록하면 B의 기기에서 보인다.
- B는 A 글을 수정·삭제할 수 없다. 화면을 우회한 REST 요청도 실패한다.
- 댓글·답글·좋아요가 다른 기기에 반영되고, 본인 것만 삭제된다.
- 비로그인은 읽기만 가능하다. 신고 목록은 다른 사용자에게 보이지 않는다.
- 업로드는 자기 계정 폴더에만 가능하고 JPG/PNG/WebP 및 3MB 한도가 저장소에서도 적용된다.
- 등록 요청 실패 시 성공으로 표시하지 않고 초안을 유지한다. 업로드 후 글 저장 실패 시 업로드 파일 정리를 시도한다.
- 계정 삭제는 현재 Supabase 운영 화면에서 처리한다. 사용자 글·댓글·좋아요는 외래 키로 삭제되며, 이미지 파일은 별도 삭제해야 한다.

## 운영 범위

게시판에는 운영진 질문 접수 기능이 없습니다. 학생 간 질문·정보·활용 사례·자유 대화를 위한 공간입니다. 신고는 `reports` 테이블에서 검토하고, 운영자는 Supabase 관리 화면에서 해당 글을 처리합니다. 신고 접수만으로 자동 삭제하거나 처리 완료를 표시하지 않습니다.

게시물 10개/시간, 댓글 60개/시간, 신고 20개/시간의 현재 보존된 행 기준 제한이 있습니다. 삭제·다중 계정까지 포괄하는 부정 사용 방지는 아닙니다. 이미지 저장량·메일 발송량·서버 비용을 관찰하고 Supabase의 인증 제한 및 운영 정책을 추가해야 합니다. 네트워크 실패로 남은 고아 이미지도 주기적으로 정리합니다.

글은 20개씩, 댓글은 100개씩 이전·다음으로 조회합니다. 제목·내용 검색은 서버에서 수행하고 말머리별로 분류합니다. 실시간 자동 갱신 대신 페이지 진입/새로고침 시 최신 정보를 가져옵니다.

공식 근거: [이메일 인증번호](https://supabase.com/docs/guides/auth/auth-email-passwordless), [행 단위 권한](https://supabase.com/docs/guides/database/postgres/row-level-security), [저장소 접근 권한](https://supabase.com/docs/guides/storage/security/access-control), [표준 업로드](https://supabase.com/docs/guides/storage/uploads/standard-uploads).
